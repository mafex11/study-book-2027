Chapter 28 of 30

Glossary: every term you may need

When and how long: Look up only when needed: a term confuses you.

What this file is: every technical term in your proposal, plus terms that are likely to come up in the interview. For each term:

  • Means: a simple definition.
  • Example: one line, usually from your own study.
  • Say it: how to explain it out loud in 1 or 2 sentences.

Facts about papers come from the PDFs in ../04_Papers/ (checked 21 Oct 2026). Examples marked "imaginary" are made up to explain the idea.

Contents: A. Agents and context files. B. Repositories and GitHub. C. Code quality. D. Experiment design. E. Statistics. F. Causal thinking. G. Research process and venues.

A. Agents and context files

Large language model (LLM)

  • Means: a model trained on a lot of text that predicts the next words. It can write code and follow instructions.
  • Example: Claude Sonnet and GPT-5 are LLMs.
  • Say it: "An LLM is the model inside the agent. The agent gives it tools and a loop so it can act."

Coding agent

  • Means: a program that uses an LLM to work on code by itself: it reads files, edits them, runs commands and tests, and repeats until it thinks the task is done.
  • Example: Claude Code, Codex, GitHub Copilot's coding agent, Devin, Cursor.
  • Say it: "A coding agent is an LLM with tools. It can read the repository, change files and run tests without a human typing each step."

Agentic coding

  • Means: writing software by giving goals to a coding agent and letting it do the steps.
  • Example: the lab's papers [1, 2] are titled around "agentic coding".
  • Say it: "Agentic coding means the developer gives a goal and the agent plans and writes the code."

Harness (also scaffold)

  • Means: the software around the model: its tools, what context it sees, and the loop that runs it. Model plus harness = agent.
  • Example: Agent Skill Evolution [11] used one research scaffold (mini-SWE-agent), not production agents like Claude Code.
  • Say it: "The harness is everything around the model. Two agents with the same model can behave differently because their harness is different."

Claude Code

  • Means: Anthropic's coding agent. It runs in the terminal and reads CLAUDE.md at the start of a session.
  • Example: Gloaguen et al. [5] ran Claude Code with Sonnet-4.5.
  • Say it: "Claude Code is Anthropic's command-line coding agent. It reads the project's CLAUDE.md."

Codex

  • Means: OpenAI's coding agent (the Codex CLI). It reads AGENTS.md.
  • Example: in [5], Codex with GPT-5.2 cost 0.32 to 0.57 USD per task.
  • Say it: "Codex is OpenAI's coding agent. It reads AGENTS.md."

Context file

  • Means: a plain text (Markdown) file in a repository that tells a coding agent about the project and its rules. The agent reads it at the start.
  • Example: a CLAUDE.md that says "Run tests with pytest" and "Put new tests in the tests folder".
  • Say it: "A context file is like a README for the agent. Developers write project rules in it, and the agent reads it before it starts."

CLAUDE.md

  • Means: the context file name that Claude Code reads.
  • Example: the lab's PROFES paper [1] studied 253 CLAUDE.md files.
  • Say it: "CLAUDE.md is the context file for Claude Code. It sits in the repository root, and Claude reads it at the start of each session."
  • Note: according to Claude Code's documentation, its content is delivered as a message after the system prompt, with "no guarantee of strict compliance". Newer Claude Code versions read AGENTS.md only if there is no CLAUDE.md. Check the docs for the version you use.

AGENTS.md

  • Means: an open, cross-tool context file name. Codex reads it, and several other agents do too.
  • Example: the Configuration Smells paper [8] studied 100 AGENTS.md and CLAUDE.md files.
  • Say it: "AGENTS.md is the shared format for agent instructions. Codex reads it."

Other instruction files

  • Means: similar files for other tools: copilot-instructions.md (GitHub Copilot), Cursor rules (Cursor IDE), SKILL.md (an Agent Skill, loaded when the agent decides it needs it).
  • Example: Agent READMEs [2] covered CLAUDE.md, AGENTS.md and copilot-instructions.md. Cai et al. [12] studied AI IDE rules. Agent Skill Evolution [11] studied SKILL.md.
  • Say it: "Different tools have different file names, but the idea is the same: rules written in plain language for the agent."

Rule (instruction)

  • Means: one sentence or bullet in a context file that tells the agent what to do or not do.
  • Example: "Use the logger, never print()".
  • Say it: "A rule is one instruction. My unit of study is one rule, not the whole file."

Token and context window

  • Means: a token is a piece of a word that the model reads. The context window is the maximum number of tokens the model can see at once.
  • Example: in BrandMemory, rules at the end of a too-long prompt were cut off.
  • Say it: "The model can only read a limited number of tokens. If the prompt is too long, something gets dropped."

System prompt vs user message

  • Means: the system prompt is the hidden base instruction from the tool maker. User messages come after it. Where an instruction sits can change how strongly it is followed.
  • Example: Harness-IF [10] studied rules placed on different "surfaces" (system prompt, project file, user instruction, tool description, skill description).
  • Say it: "The same rule can be delivered in different places. A context file is one of those places."

Headless mode

  • Means: running the agent from a script without the interactive screen. You give a task, it works, it prints a result and exits.
  • Example: claude -p "task" --output-format json or codex exec "task".
  • Say it: "Headless mode lets me run the agent from a script, so I can run hundreds of runs the same way."

Sub-agent

  • Means: a helper agent that the main agent starts for a smaller job, sometimes with a different, cheaper model.
  • Example: Gloaguen et al. [5] note that Claude Code's Task tool let Sonnet-4.5 start sub-agents using Haiku-4.5.
  • Say it: "One run can use more than one model, so I log which models were used and their cost."

Trace (agent log)

  • Means: the record of everything the agent did: tool calls, commands, files read and changed.
  • Example: [5] used traces to show the tool uv was used 1.6 times per task when the file mentioned it.
  • Say it: "A trace is the agent's step-by-step log. I have read Claude Code and Codex session logs myself while building a small tool."

Inference cost

  • Means: the money paid to the model provider for the tokens a run uses.
  • Example: [5] found context files raised inference cost by over 20% on average.
  • Say it: "Inference cost is what each run costs in API fees. It decides how many runs I can afford."

Prompt caching

  • Means: the provider saves the start of a prompt that repeats, so the next request is cheaper and faster.
  • Example: in Yuki 2.0, slimming the prompt cut the cached start of a typed request from about 32,500 to 14,800 tokens.
  • Say it: "If the same context is sent again, the provider can reuse it, which lowers cost."

MCP (Model Context Protocol)

  • Means: an open standard for connecting tools and data to an AI assistant.
  • Example: your MaxMi app gives Claude and ChatGPT access to work context through an MCP server.
  • Say it: "MCP is a standard way to plug tools and data into an AI assistant."

Temperature, seed and non-determinism

  • Means: temperature controls randomness in the model's output. A seed would make random choices repeatable. Non-deterministic means the same input can give different output.
  • Example: McMillan [7] notes Claude Code "does not expose a sampling seed", so repeated runs differ.
  • Say it: "Agents are not deterministic, so I run each condition several times."

B. Repositories and GitHub

Repository (repo)

  • Means: a project's folder of code with its full history, usually stored on GitHub.
  • Example: about 10 Python repositories from AIDev.
  • Say it: "A repository is one project's code and history."

Commit

  • Means: one saved change in git, with a message, an author and a time.
  • Example: "fix: handle empty cart" is a commit message.
  • Say it: "A commit is one saved step in the project's history."

Parent commit (and base commit)

  • Means: the commit just before a given commit. The base of a pull request is the code it started from.
  • Example: "The agent starts from the code just before the pull request", that is, the parent of the merged change. Voria et al. [9] measure quality as the change between an agent commit and its parent.
  • Say it: "The parent commit is the state just before a change. I start the agent from there, so it faces the same task as the developer."

Diff (patch)

  • Means: the lines added and removed between two versions of code.
  • Example: my checker reads the diff to find new test functions.
  • Say it: "A diff shows exactly what changed, line by line."

Pull request (PR)

  • Means: a request to merge a set of commits into the main code. Others review it first.
  • Example: AIDev holds pull requests opened by agents.
  • Say it: "A pull request is a proposed change that the team reviews before merging."

Merged PR (and squash merge)

  • Means: a pull request that was accepted into the main branch. A squash merge turns all its commits into one new commit.
  • Example: I replay merged PRs whose tests fail before and pass after.
  • Say it: "Merged means the change was accepted. Squash merges change commit IDs, so I match on the pull request, not the commit."

Agentic PR

  • Means: a pull request created by a coding agent.
  • Example: in the lab's TOSEM PR paper, 83.8% of 567 Claude Code PRs were merged, versus 91.0% of human PRs.
  • Say it: "An agentic PR is a pull request made by an agent, not a person."

AIDev

  • Means: a public dataset of agent pull requests on GitHub, by Li, Zhang and Hassan (Queen's University).
  • Example: the MSR 2026 paper version has 932,791 PRs by five agents (Codex, Devin, Copilot, Cursor, Claude Code) in 116,211 repos, cutoff 1 Aug 2025, plus a richer subset of 33,596 PRs from 2,807 repos with over 100 stars.
  • Say it: "AIDev is the main dataset of agent pull requests. The lab's papers use it, and I use it to choose repositories."
  • Note: AIDev does not contain the context files themselves or full repository history. You must clone the repositories.

Identifying agent vs human work

  • Means: deciding whether a commit or PR was made by an agent. Usually from bot account names, commit message trailers ("Generated with Claude Code") or PR metadata.
  • Example: Sawada et al. [3] matched committer names like "claude[bot]" and excluded Codex because it "does not appear as a commit owner".
  • Say it: "Labels are best effort. Agent work can be hidden if a person removes the trailer, so I treat 'human' as 'not marked as agent'."

Conventional Commits and fix commits

  • Means: a style of commit messages with a type at the start: feat, fix, refactor, docs, chore, and so on. A fix commit repairs a bug.
  • Example: Sawada et al. [3] used an automatic classifier (the Conventional Commits Classification System, 77.95% precision) and found fix was 11.73% of commits on agent-created files.
  • Say it: "I count later fix commits on agent code as one sign of maintenance, like [3] did."

Golden patch

  • Means: the real code change from the merged pull request, the "correct answer".
  • Example: Gloaguen [5] calls it X*. My agent never sees it.
  • Say it: "The golden patch is what the developer actually wrote. I only use it to build and check the task."

Test suite, unit test, pytest

  • Means: a test suite is the project's set of automatic tests. A unit test checks one small piece. pytest is the standard Python test runner.
  • Example: pytest -q tests/test_discounts.py.
  • Say it: "Tests let me check correctness automatically."

Fail-before, pass-after tests

  • Means: tests that fail on the code before a change and pass after it. They prove the change did something. SWE-bench calls them FAIL_TO_PASS tests.
  • Example: a PR adds apply_discount and its test. The test fails before (no function), passes after.
  • Say it: "If the PR's own tests fail before and pass after, I can use them to check the agent's solution."

Hidden tests

  • Means: tests the agent does not see during the run. They are added only to check the result.
  • Example: the PR's own test file is copied in after the agent finishes.
  • Say it: "The agent never sees the checking tests, so it cannot write code just to pass them."

SWE-bench

  • Means: a well-known benchmark of real GitHub issues from popular Python projects. The agent must write a patch that makes the tests pass. SWE-bench Lite has 300 tasks; SWE-bench Verified has 500 curated tasks.
  • Example: Guardrails [6] used SWE-bench Verified; Gloaguen [5] used SWE-bench Lite plus their own CTXbench.
  • Say it: "SWE-bench is the standard way to test coding agents on real issues. My task setup is similar."

Benchmark

  • Means: a fixed set of tasks used to compare systems.
  • Example: Harness-IF [10] is a benchmark; its tasks were written by the authors.
  • Say it: "A benchmark is a shared test set. Mine is closer to a replay of real project work."

Container (Docker)

  • Means: a small, isolated computer environment with exactly the software you install. It starts the same way every time.
  • Example: each agent run starts in a fresh container.
  • Say it: "A container gives every run the same clean starting point."

Environment setup

  • Means: installing the right Python version and dependencies so a project's tests can run.
  • Example: Gloaguen [5] used an agent to write setup scripts and kept PRs where at least one test passed, 87% of the filtered ones.
  • Say it: "Getting real projects' tests to run is the hardest practical part, so I start with repos whose tests already run in CI."

CI (continuous integration) and pre-commit hooks

  • Means: CI runs tests and checks automatically on every change, usually on GitHub Actions. A pre-commit hook runs checks before a commit is saved.
  • Example: a project's CI runs ruff and pytest on every pull request.
  • Say it: "CI is the project's automatic checking. If CI already enforces a rule, the context file rule may be redundant."

Repository mining

  • Means: collecting and analysing data from software repositories (code, commits, pull requests, issues) to learn about development.
  • Example: the lab's papers [1, 2, 3] are mining studies.
  • Say it: "Mining means studying what really happened in projects, from their history."

GitHub API

  • Means: the official way to fetch GitHub data (pull requests, files, commits) with code. It has rate limits.
  • Example: Agent READMEs [2] used it to find context files in AIDev repositories.
  • Say it: "I use the GitHub API to fetch data that AIDev does not include."

C. Code quality

Code quality (and proxies)

  • Means: how good code is beyond "it works": readable, simple, easy to change. We measure it with proxies (numbers that stand in for it).
  • Example: my RQ3 proxies: test results, cyclomatic complexity, static analysis warnings.
  • Say it: "Quality has no single number. I use common proxies and I say that they are proxies."

Maintainability and maintenance

  • Means: maintainability is how easy code is to fix and change later. Maintenance is the actual later work.
  • Example: Sawada et al. [3] warn: "Practitioners should therefore not assume that low maintenance frequency alone indicates high code quality."
  • Say it: "Fix commits after merge are a closer sign of real maintenance than static metrics, but still a proxy."

Linter

  • Means: a tool that checks code for style problems and simple bugs without running it.
  • Example: ruff flags an unused import (rule F401) or a line that is too long (E501).
  • Say it: "A linter checks rules automatically. If a linter already enforces a rule, writing it in the context file may add little."

Static analysis

  • Means: analysing code without running it. Linters are one kind. Others find security issues or type errors.
  • Example: ruff, pylint, pyright, Bandit, Semgrep.
  • Say it: "Static analysis reads the code and reports likely problems without executing it."

Static analysis warning

  • Means: one problem reported by such a tool.
  • Example: "unused variable", "bare except".
  • Say it: "I count warnings in the changed files, but I leave out any check that is the rule itself."

Cyclomatic complexity

  • Means: the number of independent paths through a function. Roughly: number of decisions (if, for, while, and, or, except) plus 1.
  • Example: a function with one if and one for has complexity 3.
  • Say it: "Cyclomatic complexity counts decision points. Higher means harder to test and understand. I compute it with radon, which the lab also used in its readability paper."

Maintainability Index

  • Means: a single score combining lines of code, cyclomatic complexity and Halstead metrics. Higher is better.
  • Example: the lab's readability paper found Maintainability Index decreased in 56.1% of agent readability commits.
  • Say it: "It is a combined score. I would report it only as a secondary measure."

radon, ruff, pylint

  • Means: Python tools. radon computes complexity and Maintainability Index. ruff is a fast linter. pylint is an older, stricter linter.
  • Example: radon cc -s file.py prints complexity per function.
  • Say it: "These are standard Python tools, so others can repeat my measurements."

AST (abstract syntax tree)

  • Means: the code parsed into a tree structure that a program can inspect.
  • Example: McMillan [7] checked his rule with an AST-based script. A checker for "no print()" can walk the AST and find print calls.
  • Say it: "An AST lets a script understand code structure, not just text, so checks are more accurate."

Code smell

  • Means: a sign in code that often means a deeper design problem.
  • Example: a very long function, duplicated code.
  • Say it: "A smell is a warning sign, not always a bug."

Configuration smell

  • Means: the same idea for context files: common mistakes in how they are written.
  • Example: [8] lists six: Context Bloat, Skill Leakage, Lint Leakage, Blind References, Init Fossilization, Conflicting Instructions.
  • Say it: "Configuration smells are bad patterns in agent files. My Year 2 checker would reuse their detectors."

Lint Leakage

  • Means: a rule in the context file that a linter or formatter already checks.
  • Example: [8] found it in 62% of 100 files. "Use 4-space indentation" when the formatter already does it.
  • Say it: "If the linter already enforces it, the rule in the file may be wasted space. RQ2 tests whether such rules are less effective."

Context debt

  • Means: a term from Agent READMEs [2]: context files becoming long, opaque and hard to maintain over time.
  • Example: files that only grow by small additions and are rarely cleaned.
  • Say it: "Context debt is like technical debt for agent instructions."

Technical debt and SATD

  • Means: technical debt is a shortcut that makes later work harder. SATD (self-admitted technical debt) is when developers write it in a comment, like "TODO: fix this hack".
  • Example: a big research line of the lab (for example their ICPC 2025 and TOSEM 2026 SATD papers).
  • Say it: "Technical debt is the cost of shortcuts. The lab studies how developers admit it in comments."

Refactoring

  • Means: changing code structure without changing what it does.
  • Example: renaming a function, extracting a method. The lab's "Agentic Refactoring" paper studies refactorings by agents.
  • Say it: "Refactoring improves structure but keeps behaviour the same."

D. Experiment design

Empirical study

  • Means: a study based on observed data or experiments, not only on theory or opinion.
  • Example: both parts of your plan are empirical.
  • Say it: "Empirical means I measure what actually happens."

Controlled experiment

  • Means: you change one thing on purpose, keep everything else the same, and measure the result.
  • Example: the same task, same agent, same file, except one rule is removed.
  • Say it: "In a controlled experiment I change one thing and hold the rest fixed, so the difference comes from that change."

Condition (treatment, file version)

  • Means: one setting in an experiment.
  • Example: my five conditions: original, removed, reworded, neutral, no file.
  • Say it: "Each file version is one condition."

Baseline

  • Means: the reference condition you compare against.
  • Example: "no file at all" shows the agent's default behaviour.
  • Say it: "The baseline shows what happens without the thing I am testing."

Ablation

  • Means: removing one part of a system to see how much it mattered.
  • Example: removing one rule from CLAUDE.md. Gloaguen [5] ablated whole categories; Guardrails [6] ablated each of 18 rules.
  • Say it: "Ablation means taking a part out to measure its contribution. My part is one rule."

Leave-one-out

  • Means: an ablation where you remove exactly one item and keep all others.
  • Example: remove rule R, keep the other 11 rules.
  • Say it: "I remove one rule at a time, so I know which rule caused a change."

Neutral control (placebo text)

  • Means: replacing the rule with a sentence of the same length that gives no instruction.
  • Example: "Put new tests in the tests folder." becomes "This project began as a weekend project." (both 7 words).
  • Say it: "It separates the rule's meaning from simply having text there, because random rules helped as much as expert rules in [6]."

Template rewording

  • Means: changing a rule's wording with a fixed pattern so only the form changes, not the meaning.
  • Example: "put new tests in the tests folder" to "do not put new tests outside the tests folder".
  • Say it: "A fixed template changes only the polarity, and a second person checks the meaning is the same."

Paired (within-task) design

  • Means: every condition runs on the same tasks, so you compare like with like.
  • Example: every task runs with all five file versions. Guardrails [6] also used a paired design.
  • Say it: "Each task is its own control, which removes a lot of noise."

Run and repeated runs

  • Means: one run = one agent session on one task with one file version. Repeated runs = the same setting run several times.
  • Example: 3 runs per version.
  • Say it: "Because agents are random, I repeat each setting and look at the spread."

Compliance (instruction following, adherence)

  • Means: whether the agent's output follows the rule. In my plan: the fraction of applicable places that follow it.
  • Example: 3 of 4 output statements use the logger: compliance 0.75.
  • Say it: "Compliance is how often the code follows the rule, measured where the rule applies."

Applicable place

  • Means: a place in the new code where the rule could be followed or broken.
  • Example: for "use the logger", each new output statement. For "tests in tests/", each new test.
  • Say it: "I only count places where the rule applies. If there are none, I report that run separately."

Effective rule (your definition)

  • Means: a rule that agents follow more often when it is in the file than when it is removed.
  • Example: if agents put tests in tests/ anyway, the rule is followed but not effective.
  • Say it: "Effective means the rule makes a difference, not just that the code happens to match it."

Against-prior rule (from Harness-IF)

  • Means: a rule that asks for something the agent would not do by default.
  • Example: Harness-IF [10] found every model did worse on against-prior rules, by 3.6 to 7.4 points.
  • Say it: "Rules that go against the agent's habits are the real test of following instructions."

Negative constraint vs positive directive (wording, polarity)

  • Means: negative = "do not X". Positive = "do X".
  • Example: in Guardrails [6], the 3 rules whose removal hurt were all negative ("do not refactor unrelated code").
  • Say it: "Wording is whether the rule says what to do or what not to do. I test it by flipping the same rule."

Specificity

  • Means: in your plan, whether a rule names a concrete file, folder, function, command or tool.
  • Example: "run make lint" is specific; "write clean code" is not.
  • Say it: "Specific rules name something concrete. In [11], rules naming a command or path had the biggest effect."

Script-checkable rule

  • Means: a rule whose compliance a small program can decide.
  • Example: test location, no print(), maximum line length, using a named command.
  • Say it: "I only use rules a script can check, so my results speak for that kind of rule."

Checker accuracy: precision and recall

  • Means: precision = of the cases the checker flagged, how many were right. Recall = of the real cases, how many the checker found.
  • Example: I hand-check at least 20 examples per checker and report how many it got right.
  • Say it: "Before I trust a checker, I measure how often it is right."

Inter-rater agreement (Cohen's kappa)

  • Means: how much two people agree when labelling the same items. Kappa corrects for agreement by chance (1 = perfect, 0 = chance).
  • Example: the lab's readability paper reports Cohen's kappa 0.80 between annotators.
  • Say it: "When a second person checks my rewordings, I can report how often we agreed."

LLM-as-a-judge

  • Means: using an LLM to decide if an output is good or follows a rule.
  • Example: Cai [12] used Gemini 3 Flash Preview to judge compliance; Harness-IF [10] used a judge for 86.8% of verdicts.
  • Say it: "It covers more rule types but it is less stable. I use scripts so the measurement is repeatable."

Pilot study

  • Means: a small first version of the study to test the setup and get real numbers before the main study.
  • Example: a pilot on two repositories sets the final numbers and budget.
  • Say it: "A pilot is a small trial run. It tells me cost, time and variance before I commit the budget."

Reproducibility and version pinning

  • Means: others can repeat the study and get similar results. Pinning means fixing the exact software and model versions.
  • Example: McMillan [7] pinned Claude Code CLI at 2.1.92 and logged model ID, file hashes and tokens for every run.
  • Say it: "I pin the agent and model versions and release all scripts, so others can repeat the runs."

Version drift

  • Means: results change because the agent software or model changed during the study.
  • Example: McMillan reported Opus 4.7 runs only descriptively because they needed a different CLI version.
  • Say it: "Agents change every few weeks, so I run all conditions in the same short time window, in random order."

Training cutoff

  • Means: the date after which the model has seen no training data.
  • Example: a pull request merged after the cutoff cannot be in the training data.
  • Say it: "I prefer tasks from after the cutoff, so the model cannot remember the answer."

Contamination (data leakage)

  • Means: test data was in the model's training data, so results look better than they should.
  • Example: Gloaguen [5] split tasks by the models' cutoff and found no significant or consistent difference, but I still prefer post-cutoff tasks.
  • Say it: "Contamination means the model may have seen the answer. I reduce it with newer tasks and I report old and new tasks separately."

Canary test (isolation check)

  • Means: a small test with an unusual instruction to prove a setting is or is not being loaded.
  • Example: put "end your answer with PINEAPPLE" in a user-level file, run, and check PINEAPPLE never appears in the clean setup.
  • Say it: "A canary proves that my isolation works, so no hidden instructions leak into runs."

Ceiling and floor effects

  • Means: if almost every run follows the rule (ceiling) or almost none does (floor), you cannot see a difference between conditions.
  • Example: if agents always put tests in tests/, removing the rule cannot lower it much.
  • Say it: "If agents already do it, there is no room to measure an effect. That itself is a finding: the rule may be redundant."

Random run order (interleaving)

  • Means: running conditions in a random, mixed order rather than one block after another.
  • Example: do not run all "original" runs on Monday and all "removed" runs on Friday.
  • Say it: "If the API changes during the week, it affects all conditions equally."

E. Statistics

Proportion (rate)

  • Means: a count divided by a total.
  • Example: 3 of 4 places followed = 0.75.
  • Say it: "Compliance is a proportion."

Logistic regression

  • Means: a model for yes/no outcomes. It predicts the probability of "yes" from some variables, using log-odds.
  • Example: probability that a test is placed in tests/, given the file version and the agent.
  • Say it: "Logistic regression is regression for yes/no outcomes. It tells me how a factor changes the odds of yes."

Odds and odds ratio

  • Means: odds = p / (1 - p). An odds ratio compares the odds in two conditions. OR = 1 means no difference.
  • Example: if p = 0.8, odds = 4. If removing the rule gives odds 1, the odds ratio is 4.
  • Say it: "An odds ratio of 2 means the odds of following the rule are twice as high."

Mixed effects model (GLMM)

  • Means: a regression with both fixed and random effects. For yes/no outcomes it is a generalized linear mixed model (GLMM).
  • Example: followed ~ version + agent + (1 | task) + (1 | rule). McMillan [7] used lme4::glmer in R.
  • Say it: "A mixed model handles data in groups, like many runs per task and per rule."

Fixed effect

  • Means: a variable whose specific levels you care about and want to estimate.
  • Example: file version (original, removed, ...) and agent (Claude Code, Codex).
  • Say it: "Fixed effects are what I manipulate and want to measure."

Random effect (random intercept, random slope)

  • Means: a variable whose levels are a sample from a larger group. Each level gets its own baseline (random intercept). A random slope lets the effect differ by level too.
  • Example: tasks and rules. Some rules are followed 90% by default, some 20%. A random slope for version by rule would let the removal effect differ per rule.
  • Say it: "Random effects account for the fact that some tasks and rules are just easier, so my result generalises beyond these exact tasks and rules."

Fixed vs random, in one line

  • Say it: "Fixed: things I chose and want to estimate. Random: things I sampled and want to generalise over."

Repeated measures (nested data)

  • Means: many observations come from the same unit, so they are not independent.
  • Example: 30 runs on one task; many places in one run.
  • Say it: "Runs on the same task are similar, so I cannot treat them as independent."

p-value

  • Means: if there were really no effect, the chance of seeing a result at least this extreme.
  • Example: [5]: developer files +2.4%, p = 0.21, so not significant.
  • Say it: "A small p-value means the result would be surprising if there were no effect. It does not say how big the effect is."

Confidence interval

  • Means: a range of plausible values for the true effect.
  • Example: an odds ratio of 2.0 with a 95% interval from 1.3 to 3.1 (imaginary).
  • Say it: "I report intervals, not just p-values, so people see the size and the uncertainty."

Effect size

  • Means: how big a difference is, not just whether it exists.
  • Example: a drop from 80% to 50% compliance is a large effect.
  • Say it: "Effect size tells you if the difference matters in practice."

Statistical power

  • Means: the chance that a study detects an effect if it is really there. Low power = real effects are missed.
  • Example: McMillan [7] planned 50 runs per condition and reported at least 98% power for a 15-point change.
  • Say it: "With 3 runs, power for one rule alone is low. The main test pools all rules, and the pilot will tell me how many runs I need."

Power analysis by simulation

  • Means: you simulate fake data with the variance you saw in the pilot, run your model many times, and see how often it finds a given effect.
  • Example: simulate 30 rules x 2 tasks x 3 runs with a 15-point effect, count how often the model detects it.
  • Say it: "I would use the pilot's variance to simulate the study and choose the number of runs."

Multiple comparisons (Holm, Benjamini-Hochberg)

  • Means: if you run many tests, some will be "significant" by chance. Corrections adjust for that.
  • Example: Guardrails [6] say their only significant single rule (p = 0.016) "would not survive a strict multiple-comparison correction across all 18 rules".
  • Say it: "With 30 rules, I correct for many tests, and I treat single-rule results with care."

McNemar's test

  • Means: a test for paired yes/no data (the same task under two conditions).
  • Example: Guardrails [6] and Gloaguen [5] used it to compare pass rates.
  • Say it: "McNemar compares two conditions on the same tasks. A mixed model does this for many conditions at once."

Kruskal-Wallis test and Cliff's delta

  • Means: Kruskal-Wallis compares several groups without assuming normal data. Cliff's delta is an effect size for "how often one group is bigger than the other".
  • Example: Voria et al. [9] plan Kruskal-Wallis with post-hoc tests; Agent READMEs [2] report Cliff's d.
  • Say it: "These are common in mining studies, where data are skewed."

Bayes factor

  • Means: how much the data support one hypothesis over another. BF10 below 1 supports "no effect".
  • Example: McMillan [7] supported his null results for size and conflict with Bayes factors of 0.05 to 0.10.
  • Say it: "A Bayes factor can show evidence for no effect, not just a failure to find one."

F. Causal thinking

Association vs causation

  • Means: association = two things change together. Causation = one makes the other change.
  • Example: in real PRs, compliance rising after a rule is added is an association. In my experiment, removing the rule while everything else is fixed supports causation.
  • Say it: "My controlled experiment can show cause for the rule and its wording. The real PR study and the rule properties can only show association."

Confound (confounder)

  • Means: a third factor that affects both the cause and the outcome, making a false link.
  • Example: a project adds a rule and a new linter on the same day. Compliance goes up, but because of the linter.
  • Say it: "A confounder is another reason for the same change. I remove linter-change cases for that reason."

Regression to the mean

  • Means: after an unusually bad period, things often get better by themselves.
  • Example: developers add a rule right after agents break it many times (Cai [12]: 77.78% change rules to correct AI errors). Next month looks better even without the rule.
  • Say it: "Rules are added at the worst moment, so improvement afterwards is partly natural. That is why I need a comparison group."

Selection bias

  • Means: the cases you look at are not representative because of how they were chosen.
  • Example: comparing only "runs that complied" with those that did not; complying runs may be easier tasks.
  • Say it: "I compare the conditions I assigned, not the runs that happened to comply."

Counterfactual

  • Means: what would have happened without the change.
  • Example: "the same task, same agent, without rule R" is the counterfactual for "with rule R".
  • Say it: "An experiment lets me run the counterfactual directly."

Quasi-experiment and natural experiment

  • Means: a study that looks like an experiment but the change was not assigned by the researcher, it happened in real life.
  • Example: a project adding a rule to AGENTS.md on a known date.
  • Say it: "A natural experiment uses real changes, but I cannot rule out other causes."

Before-and-after study

  • Means: compare a measure before and after an event, in the same unit.
  • Example: Agent READMEs [2]: indentation violations 60.82% before vs 11.03% after the rule, in one Claude Code repo.
  • Say it: "Before and after alone is weak, because other things change over time."

Difference-in-differences

  • Means: compare the before-after change in a treated group with the before-after change in a comparison group.
  • Example: agent PRs (affected by the rule) vs human PRs in the same repo around the rule date. The file is not written for humans, although people may read it too, so this comparison is imperfect and tends to hide differences.
  • Say it: "If agent PRs improve more than human PRs after the rule, the rule is a more likely reason."

Interrupted time series

  • Means: look at a trend over many time points, and check for a jump or slope change at the event.
  • Example: monthly compliance of agent PRs, with the rule date as the break.
  • Say it: "It checks whether the trend changed at the rule date, not just the average."

Validity (internal, external, construct) and threats to validity

  • Means: internal = is the cause really what I think? External = does it generalise? Construct = am I measuring the right thing? Threats to validity is the paper section that lists these risks.
  • Example: internal: version drift. External: only Python, only script-checkable rules. Construct: complexity as a proxy for quality.
  • Say it: "Every study has limits. I list them under threats to validity and say what I did about each."

G. Research process and venues

Research question (RQ)

  • Means: a precise question the study answers.
  • Example: RQ1: does removing one real rule change how often agents follow it?
  • Say it: "Each RQ maps to one analysis."

Taxonomy

  • Means: a structured set of categories.
  • Example: Agent READMEs [2] has a 16-category taxonomy of instructions.
  • Say it: "A taxonomy is a classification scheme."

Registered report (Stage 1 and Stage 2)

  • Means: a paper where the plan is peer reviewed and accepted before data are collected (Stage 1). Results come later (Stage 2).
  • Example: Voria, Kashiwa et al. [9] is a Stage 1 registered report at ICSME 2026, with no results yet.
  • Say it: "A registered report fixes the plan in advance, which protects against changing the analysis after seeing data."

Preprint and arXiv

  • Means: a paper shared publicly before (or without) peer review. arXiv is the main site.
  • Example: Gloaguen [5], Guardrails [6] and McMillan [7] are arXiv preprints.
  • Say it: "Many papers I cite are preprints, so I treat them with some care."

Peer review, conference vs journal, short paper

  • Means: peer review = experts check a paper before it is accepted. In software engineering, conferences are main venues; journals allow longer papers. Short papers present early results.
  • Example: the PROFES paper [1] is a short paper; Agent READMEs [2] is a journal paper (TOSEM).
  • Say it: "Conferences are fast; journals allow longer, more complete work."

Replication package (open data)

  • Means: the scripts and data released so others can repeat the study.
  • Example: Agent READMEs [2] and Sawada [3] both have public replication packages.
  • Say it: "I will release all scripts, rules, file versions and run data."

Mining challenge

  • Means: a track at MSR where everyone studies the same given dataset.
  • Example: the MSR 2026 Mining Challenge used AIDev. The lab's "What to Cut?" paper won a Distinguished Mining Challenge Paper Award (3 of 116 submissions).
  • Say it: "A mining challenge is a shared-dataset track at MSR."

MSR

  • Means: the International Conference on Mining Software Repositories.
  • Example: AIDev [4] is an MSR 2026 paper.
  • Say it: "MSR is the main venue for studies that mine software data."

ICSME

  • Means: the International Conference on Software Maintenance and Evolution.
  • Example: Voria, Kashiwa et al. [9] is at ICSME 2026.
  • Say it: "ICSME is about how software is maintained and evolves, which fits rules and code quality."

EASE

  • Means: the International Conference on Evaluation and Assessment in Software Engineering.
  • Example: Sawada et al. [3] is an EASE 2026 short paper.
  • Say it: "EASE focuses on empirical evaluation in software engineering."

TOSEM

  • Means: ACM Transactions on Software Engineering and Methodology, a top journal.
  • Example: Agent READMEs [2] is accepted at TOSEM.
  • Say it: "TOSEM is a leading software engineering journal."

PROFES

  • Means: the International Conference on Product-Focused Software Process Improvement.
  • Example: the lab's Manifests paper [1] is a PROFES 2025 short paper.
  • Say it: "PROFES is about software processes and improvement."

Other venues you may hear

  • SCAM: Source Code Analysis and Manipulation (Configuration Smells [8], 2026).
  • ESEM: Empirical Software Engineering and Measurement.
  • ICSE: International Conference on Software Engineering, the largest SE conference.
  • SANER: Software Analysis, Evolution and Reengineering (a lab paper on refactoring detection, 2026).
  • Say it: "These are the main software engineering venues; MSR, ICSME and EASE fit my study best."

JST FOREST (and ACT-X)

  • Means: funding programmes of the Japan Science and Technology Agency. FOREST supports independent researchers over several years. ACT-X supports young researchers.
  • Example: Assoc. Prof. Kashiwa's FOREST project "Quality Assurance Foundation for AI-Driven Software Development" (from Aug 2026). PhD student Kosei Horikawa has an ACT-X project on test quality for AI-driven development.
  • Say it: "Kashiwa's FOREST project is about quality assurance for AI-driven development, which is close to my question."
