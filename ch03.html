Part 1: Before Monday (23 to 26 Oct)

Chapter 3 of 30

Mock interview: the questions for your friend to ask

When and how long: Sunday: give this page to a friend. 30 minutes: your slides, then the 20 core questions; the extra ones if there is time.

For the friend: you play Dr. Zhenlan Ji and Dr. Brittany Reid, the two assistant professors who will interview Sudhanshu on Monday. Dr. Ji works on causality and AI agents, so his questions are about cause and effect, experiments and statistics. Dr. Reid co-wrote the lab's papers on context files (CLAUDE.md, AGENTS.md) and builds developer tools, so her questions are about data, tools and their papers. You do not need to understand the answers. Just ask, listen, and push when an answer is vague.

How to run it (30 minutes)

  1. Use a video call if you can (Google Meet), so he practises sharing his screen. In person also works.
  2. Follow the order below. Part 1, then let him present, then Part 2. Use Part 3 only if there is time or for a second round.
  3. Push when an answer is vague. Use these follow-ups: "Why?", "Can you give an example?", "How would you check that?", "What if that is not true?"
  4. Watch the time. If one answer goes past about 1 minute, say "Thank you, let's move on." Real interviewers do this.
  5. Write down every question where he hesitated, bluffed, or talked too long. Give him the list at the end, with the checklist in Part 4.

Each question shows who would ask it, and "Listen for": the points a good answer includes. Do not read the "Listen for" part out loud.

Part 1. Opening (2 minutes)

Say:

Hello Sudhanshu. I am Zhenlan Ji, and this is Brittany Reid. Thank you for joining us today. Can you hear us well?

Then:

Please introduce yourself and your research topic. You can share your screen if you prepared slides.

Let him present (about 6 minutes). Do not interrupt. Note the time when he starts and stops.

Part 2. Core questions (about 18 minutes, ask all of them)

Warm-up

1. (Dr. Reid) Why did you choose our lab? Which of our papers have you read? Listen for: names specific papers (the Manifests paper on CLAUDE.md, the Agent READMEs paper, the pull request paper); says what he wants to learn (mining repositories, measuring quality).

2. (Dr. Ji) In one minute: what exactly is new in your study compared with existing work? Listen for: the combination of three things (one real rule at a time, real tasks from the same repositories, scripts that measure both compliance and code quality). He should NOT say "nobody has ever done this".

About the research plan (Dr. Reid)

3. (Dr. Reid) Our Agent READMEs paper already checked an indentation rule before and after it was added. What does your study add? Listen for: a controlled test (same task, same code, only the file changes), about 30 rules and two agents, code quality too; their paper itself says two cases cannot prove cause and effect.

4. (Dr. Reid) How do you know your rule checkers are correct? And what share of real rules can a script check? Listen for: checks each script by hand on at least 20 examples and reports accuracy; only rules a script can check, so results do not cover design or process rules; the pilot will count the share.

5. (Dr. Reid) How will you build your tasks? Are there enough pull requests whose tests fail before and pass after? Listen for: replays merged pull requests with the file as it was then; the task text does not mention the rule; the pilot counts how many usable ones exist; prefers ones merged after the models' training cutoff.

About the research plan (Dr. Ji)

6. (Dr. Ji) What is your treatment, what is your control, and what could confound it? Listen for: treatment = the version of the file; every task runs with every version, so each task is its own control; wording is tested directly; specificity and linter coverage are only associations.

7. (Dr. Ji) What does the neutral sentence control for? Listen for: it has the same length but no instruction, so it separates the rule's meaning from just having more text in the file.

8. (Dr. Ji) You remove one rule at a time. What if rules interact? Listen for: admits it is a limit; each rule is measured with the rest of the real file in place; could test a few pairs; mentions that Zhang et al. found 2 of 5 rule pairs were not additive.

9. (Dr. Ji) Compliance is a share. Why logistic regression? And are 3 runs enough? Listen for: compliance is a count out of applicable places, so a logistic model for counts fits; for RQ2 the rule property interacts with the file version; the main test pools all rules; the pilot sets the number of runs.

10. (Dr. Ji) If code quality changes, how do you know it changed because the rule was followed? Listen for: he compares file versions, not runs that happened to follow the rule; he leaves out checks that encode the rule itself; he does not claim more than that.

11. (Dr. Ji) Gloaguen and colleagues say agents follow instructions. So why is your first question still open? Listen for: they compared whole files and looked at tool use, not single rules checked in the code; "followed" is not the same as "effective".

12. (Dr. Ji) Public pull requests may be in the models' training data. Is that a problem? Listen for: prefers pull requests merged after the training cutoff; reports older ones separately to check.

About his work and projects

13. (Dr. Ji) Tell us about your BrandMemory A/B test. What were the two sides? Listen for: the same product demo made twice on the live system, without and with the rules; counted contractions (6 to 0) and "you/your" (15 to 1); one output on each side, so not a study.

14. (Dr. Reid) Tell us about Yuki. What did you build yourself? Listen for: Yuki for Mac started as a fork of the open source MacOS-Use project, which he credits; his own additions (tool retrieval, a hard stop for repeated actions, native app tools, the Mac app, memory); Yuki 2.0 is his rewrite for Windows.

15. (Dr. Reid) How do you use coding agents and context files at work? Listen for: uses Claude Code and Codex every day, reviews every change, maintains the CLAUDE.md and AGENTS.md files; gives one concrete example of a rule. He must NOT say agents write most of his code.

Practical questions

16. (Dr. Reid) Would you start in April or October 2027? How will you fund your studies? Listen for: prefers October so he can apply for the IPGP scholarship through the lab; April is possible; backup is savings and family support, then JASSO.

17. (Dr. Ji) You work full time now. What will you do about your job? Listen for: will leave Layerpath before enrolling and study full time.

18. (Dr. Reid) How is your Japanese? Listen for: honest: beginner, below N5, studying every day with Genki I and an app.

19. (Dr. Ji) The full experiment costs about 1,300 to 1,900 dollars. Who pays? Listen for: it is an estimate; the pilot (about 265 to 375 dollars) he can pay himself; would ask if it fits a lab budget, otherwise reduce runs. He must NOT say the lab will pay.

Closing

20. (Dr. Ji) Do you have any questions for us? Listen for: one good question, ideally about applying for the IPGP scholarship with the lab's support (deadline 13 November).

Then say:

Thank you, Sudhanshu. We will be in touch.

Part 3. Extra and harder questions (if there is time, or for a second round)

Pick any 5 to 10. These are the tough ones.

About novelty and their papers

  1. (Dr. Reid) Isn't your study just the future work from our Manifests paper?
  2. (Dr. Ji) Harness-IF already tests single rules with the rule withheld. What is new in yours?
  3. (Dr. Reid) A study on Agent Skill files already showed that adding a rule changes what agents do. How are you different?
  4. (Dr. Reid) What did you learn from our pull request paper?
  5. (Dr. Ji) Isn't this just an A/B test? Where is the research?

About the design

  1. (Dr. Ji) Claude Code reads CLAUDE.md and Codex reads AGENTS.md. Is "agent" a clean factor?
  2. (Dr. Ji) How do you reword a rule without changing its meaning?
  3. (Dr. Ji) What if a file version changes whether there is any place where the rule applies at all?
  4. (Dr. Reid) If all tests are already in the tests folder, the agent copies that anyway. What if most rules show no effect?
  5. (Dr. Reid) Why only Python? Would rules work the same in npm or JavaScript projects?
  6. (Dr. Reid) Why not use an LLM to judge whether a rule was followed?
  7. (Dr. Reid) If a linter can check a rule, why should the rule be in the context file at all?
  8. (Dr. Ji) Your results hold for two agents at fixed versions. Will they mean anything next year?

About the real pull request study and the tool

  1. (Dr. Reid) In real pull requests, how do you tell agent work from human work? What about rules added right after a violation?
  2. (Dr. Reid) How will you test your checker tool with developers? How many, and compared against what?

About statistics and causality

  1. (Dr. Ji) What is an odds ratio, in simple words?
  2. (Dr. Ji) Give one example of correlation versus causation in your own plan.

About him

  1. (Dr. Reid) You have no research publication. Why should we believe you can do research?
  2. (Dr. Ji) Did you use AI tools to write your proposal?
  3. (Dr. Ji) Which part of your plan are you least sure about?
  4. (Dr. Ji) If we asked you to change your topic toward our area, would you?
  5. (Dr. Reid) Your proposal mentions Burnt. What is it?
  6. (Dr. Reid) Did you test Magic Editor with real users?
